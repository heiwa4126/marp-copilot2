# VS Code × GitHub Copilot

## 開発の流れに、AI の相棒を組み込む

初心者から開発者まで、今日から使える基本とコツ

---

## 1. Copilot の役割

## 「答えを出す」より「考える時間を増やす」

- コードの候補を提案し、入力と調査の時間を短縮
- エラーの原因や実装方針を対話で整理
- テスト、ドキュメント、レビューの下書きを支援
- 最終判断と責任は、コードを書く開発者にある

> Copilot は自動操縦ではなく、速いペアプログラマー

---

## 2. VS Code での導入と画面

## まずは「見える場所」を覚える

1. VS Code に GitHub アカウントでサインイン
2. **GitHub Copilot** 拡張機能をインストール
3. エディターで候補、サイドバーでチャットを確認

| 場所            | できること               |
| --------------- | ------------------------ |
| エディター      | 入力中のコード補完・提案 |
| Chat ビュー     | 質問、説明、方針の相談   |
| インライン Chat | 選択範囲への短い修正依頼 |

---

## 3. Chat / Ask / Edit / Agent

## 目的に合わせてモードを選ぶ

- **Ask**：仕組みを知る、エラーの意味を聞く
- **Edit**：複数ファイルにまたがる変更案を作る
- **Agent**：タスクを分解し、実装と検証を進める
- **Chat**：上記を含む対話の入口。質問を具体化する

### 迷ったら

まず Ask で状況を整理し、変更範囲が明確になったら Edit。複数手順の作業は Agent。

---

## 4. コード補完と生成

## 小さな意図を、コードの近くに置く

```ts
// 期限切れのセッションを除外し、作成日時の新しい順に返す
function activeSessions(sessions: Session[], now: Date) {
	return sessions
		.filter((session) => session.expiresAt > now)
		.sort((a, b) => b.createdAt.getTime() - a.createdAt.getTime());
}
```

- 関数名、型、コメントで意図と制約を示す
- 候補は `Tab` で受け入れ、不要なら `Esc`
- 生成後に境界値、例外、パフォーマンスを確認

---

## 5. リファクタリング・テスト・デバッグ

## 作業を「観察 → 変更 → 検証」に分ける

- **リファクタリング**：対象範囲と「変えない振る舞い」を指定
- **テスト**：正常系、境界値、失敗系を先に列挙
- **デバッグ**：再現手順、エラーログ、期待値を渡す

### 依頼例

> `parseDate` の失敗原因を調べて。既存テストを壊さず、タイムゾーンを含むケースを追加し、テストを実行して結果を説明して。

---

## 6. 指示の出し方とコンテキスト

## 良い依頼は「目的・範囲・条件・確認」を含む

- **目的**：何を実現したいか
- **範囲**：変更してよいファイル、触らない場所
- **条件**：言語、API、互換性、既存パターン
- **確認**：実行するテスト、期待する出力

### コンテキストを整える

関連ファイルを開く、シンボルや選択範囲を指定する、エラー全文を渡す。秘密情報は貼らない。

---

## 7. セキュリティ、検証、まとめ

## 速さと信頼性を同時に守る

- API キー、個人情報、顧客コードをプロンプトに入力しない
- 提案コードの依存関係、権限、入力値検証をレビューする
- テスト、型チェック、lint、実行結果を自分の環境で確認する
- 不明なコードは採用せず、理由を質問して理解する

### 今日の一歩

1. Ask で小さな疑問を聞く
2. 補完を一つ受け入れる
3. テストで結果を確かめる

> 便利さを使いながら、判断力は手放さない
